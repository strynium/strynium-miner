# 服务端 R18 / 本地加密端 D14 · 2026-11-01

## 更新范围

本次修复只发生在本地加密端 D14。已经运行 R18 的服务器无需重装或重启。Windows / Linux / Ubuntu 三个服务端包复用 R18 / D13 发布的完整原始字节，保留原 SHA-256；Ubuntu 服务端包仍使用 `20261031.r18` 文件名。D14 本地端包使用新的构建与独立校验信息，Ubuntu 包日期为 `20261101.d14`。

## 连接与日志修复

原本已成功双向转发的矿机会话，30 秒没有新份额或新任务也可能被误当成读取故障关闭。现在只有同一会话成功转交非空上行数据并成功写回非空下行数据后，才取消业务静默截止；正常等待由真实连接与隧道生命周期维持。初始通信等待、EOF、读取失败、云端流关闭、连接数/队列限制及写入/转交超时保留，不伪造矿机心跳、任务或份额。双向转发阶段不代表矿池鉴权或硬件身份。

接入和关闭原因合并到原运行日志，包含时间、端口、局域网端点、会话编号、双向阶段和转交字节数。停止或重新应用配置后的最后一批事件也保留。日志不记录协议正文、矿池账号密码、授权或密钥；监听事件最多 256 条、控制台最多 500 条，均仅内存保留。进程崩溃或强制中止不能保证每条会话都有最终事件；云端流关闭/转交通道不可用按可观测范围合并描述。

## 验证证据与限制

- 旧代码静默回归先失败，修复后通过。本地端最终原生 **debug** 回归 185 通过、0 失败、4 原有浏览器环境/子进程夹具忽略；忽略不算通过。没有将历史 R18 数量或重复专项累加进本轮数量。
- 真实 TCP + TLS/MPT1 隔离回显测试使用生产监听限制：双向传输后静默 90 秒，业务字节数不增加，原流与授权连接保持，之后在同一 TCP 继续收发。只有隧道控制心跳，没有伪造矿机业务数据。
- 无数据、仅上行、仅下行及空下行仍触发初始等待超时。真实 EOF、下行关闭、背压、容量与隔离用例通过；停止后的最后日志、日志不重复和载荷不泄漏用例通过。
- 本地 UI 19 项通过，全目标 Clippy `-D warnings` 通过。正式 release 程序另行构建并检查，构建/包校验/隔离启动证据以本版发布清单为准；以上 185 项不能称为 release-profile 测试。
- 没有修改服务端 Fee 费率、身份、调度截止时间或账本；没有验证所有 ASIC、Windows / 浏览器版本或 Linux 发行版。隔离结果不能替代矿场 D14 长时间验收，也不证明物理算力、拒绝率目标或多个完整抽水周期已达标。

## 更新

Linux / Ubuntu 使用首页一键命令，选择 **2 本地加密端 → 1 安装 / 更新**，更新后仍需解锁并应用启动。Windows 从托盘退出旧版本后完整解压 D14 包，用原用户启动并保留原数据目录。初始窗口宽 59%、高 73%，X 缩小到托盘、右键退出的行为保持不变。服务端新装可继续选择菜单 1 → 1，获得原 R18 包。

至少 30 分钟仅是初步连接观察；平台抽水的现场验收须覆盖多个完整周期。旧 R18 / D13 发布保留供回溯，不随本次更新清理生产数据。
