# 服务端 R20 / 本地加密端 D14 · 2026-11-01

## 更新范围

本轮修改服务端抽水新连接的准备流程，重新构建 Windows / Linux / Ubuntu 三个 R20 服务端包。本地加密端三个 D14 包逐字节复用 R18 / D14 原包，原 SHA-256、原文件名和构建来源保留；已有 D14 无需重复安装。

产品版本保持 **v1.0.0**，界面不展示内部 R20 / D14 构建编号；构建编号保留在发布标签、软件包和清单中供追溯。

## 需要修复的问题

平台抽水使用占比较小的算力。新连接若立即以很高的矿池份额难度工作，一份被接受的工作量可能覆盖较长的抽水额度，随后必须等待，矿池曲线便可能出现明显空档。池端判为离线并不能单独证明 TCP 已断开；保持 TCP 连接也不能替代有效份额。

R20 将新连接准备与实际收费调度分开，处理高初始难度造成的长等待。它不更改矿池自己的难度规则，也不会减少之前已经形成的工作信用来提前收费。

## 新连接的准备流程

1. BTC / BCH 新建抽水连接完成真实订阅与授权后，由独立接收任务维护该连接的实际难度、nonce 和版本掩码；矿机继续执行用户主池任务。
2. 以当前算力估计、设定费率和 120 秒预算计算准备门限，使用精确整数工作量比较。单份工作量不高于门限时结束准备，不固定指定某个矿池难度。
3. 每个端口的抽水运行实例最多同时准备 4 条连接。准备不会长期占用实际抽水所有权名额，也不会阻塞同矿机其他可用目标或其他矿机的就绪连接。
4. 准备最多等待 600 秒。有有效难度但仍较高时保留真实上下文作为有界回退；缺少有效难度则关闭该连接并按已有故障恢复规则处理。不靠修改矿池密码、伪造份额或重连循环强迫矿池降难度。
5. 就绪后重新由调度器按当前身份、配置、算力和旧计划选取正式轮次。准备期间没有创建收费轮次、份额记录或账本工作量；准备门限不是最终计费预算。
6. 正式接管时丢弃准备阶段的任务积压，使用当前难度与 nonce，并等待下一条矿池实际下发的任务。普通准备后复用连接最多等待 120 秒；熔断半开探测仍走原有短期限，不被 600 秒准备延长。

准备期间的 EOF、非法上下文或无难度超时只向原有目标熔断器报告一次。取消、主动停止或 owner 失效不记作矿池故障。新日志按匿名目标编号和会话编号关联，不记录矿池密码、矿工账号或协议正文。

## 账本、恢复与原有连接复用

历史逻辑身份、费率、精确账本、已经形成的工作信用和剩余等待全部保留。更新后旧高难度份额对应的等待仍可能继续；不会回写旧份额难度或清账来制造曲线平滑。结果未知的提交不重投、不伪装为接受。

正常收费轮次结束后，仍须确认客户任务恢复、旧任务退休及闭合账本实际持久化，才允许物理连接继续复用。缓存最多 256 条，仅淘汰空闲连接；正常轮次后的空闲保留期按剩余等待加 15 分钟计算，最低 30 分钟、最高 2 小时。身份、目标、矿机会话、版本掩码和配置修订不同的连接不会混用。

## 实测依据与边界

生产抓包曾确认，同一条抽水连接持续接收任务，矿池难度从 262144 降到 8192；观察者页面仍会在超过 10 分钟没有新份额后显示离线。独立的新连接观察还验证了不提交份额时可收到矿池主动降难度。这些是特定 BTC 节点的实际行为证据，不是所有矿池的协议保证。

本版不强制外部矿池难度，不伪造任务或份额，不用延迟/重发提交维持在线。小算力、随机出份、矿池统计窗口和多矿机数量仍影响曲线；不保证固定每分钟产生有效份额，也不保证每个短窗口或任意 24 小时都精确等于设置比例。上线后需要同时核对用户主池与平台目标的接受工作量，覆盖多个完整周期。

## 验证与升级

本版四个相关 crate 的完整原生回归：**1416 通过、0 失败、11 忽略**；测试配置为 `test opt-level=1; debug assertions and overflow checks enabled`。控制台测试：**72 通过、0 失败、0 跳过**；相关 crate 的全部目标通过 Clippy `-D warnings` 检查。忽略与跳过不计为通过，局部测试不重复累计。

Windows / Linux 服务端由正式入口重新进行 release 构建；两端均通过独立临时目录、仅本机回环地址的 HTTPS 启动与管理员设备 API 检查，读取至少两次真实设备样本，间隔不少于 1 秒，并核对产品版本与构建标识。测试进程均已退出。

6 个软件包已完成逐文件、许可清单、内外校验和与隐私检查：三个 R20 服务端包采用本轮新构建，三个 D14 本地端包与原发布逐字节相同。管理脚本已通过服务端与本地端选包、解压、校验和二进制版本检查。这些是本地包与管理脚本验证，不替代发布后的在线下载复核或真实矿场长期验收。

最终原生回归、静态检查、界面检查、正式构建、Windows / Linux 隔离启动、六包字节与许可检查分别记录，不能相互替代。完整结果见 [VERIFY.md](../VERIFY.md) 和最终发布清单。前期局部测试与完整回归不重复累加。

Linux / Ubuntu 使用首页一行命令，选择 **1 服务端 → 1 安装 / 更新**。Windows 正常退出旧服务端，完整解压 R20 包，使用原用户和数据目录。管理器先备份再更新，保留账号、端口、证书、授权及账本，健康检查失败时回退。服务更新会短暂重启。

D14 本地端继续使用现有安装，窗口比例、托盘行为与转发方式保持不变。软件包的实际字节数、SHA-256 和组件来源已列入本版发布清单；R20 服务端使用本轮实际软件包的大小与校验值。
