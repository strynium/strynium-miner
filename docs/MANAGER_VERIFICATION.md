# Linux 管理器 1.0.0 验证记录

## 1.0.1 安装入口补充验证 · 2026-10-28

新增 14 项隔离 chroot 场景：复用已有组件；apt/dnf/yum/pacman/zypper 自动准备分支；系统版本过旧、软件源未知、安装失败、无 systemd 时明确退出；普通账号自动申请 sudo、没有 sudo 时指导 root 登录；复制入口对已有/缺失 curl 的处理。软件源命令使用隔离替身，未修改宿主软件源，不等于这五类发行版均已实机验证。

离线回归现为 9 项，新增管理命令自动申请权限、缺少账号维护库时自动准备两项。原先 20 项 R14/D11 服务维护集成场景保持原验证范围；本次未改动其安装、备份或回退实现。

以下为 1.0.0 的原始验证记录。

日期：2026-10-28。目标为已发布的服务端 R14、本地加密端 D11；软件二进制未重新编译或替换。

环境：Ubuntu 26.04 x64 / WSL2，真实 systemd。使用独立临时目录、独立服务名和普通运行用户；未操作生产服务或矿场数据。

## 通过的检查

14 项安装维护集成场景：

1. 首次 Web 随机端口的范围与可用性。
2. 至少 8 位密码及字符要求，拒绝把公开初始密码用作新密码。
3. 拒绝路径穿越、归档链接与错误 SHA-256。
4. 真实服务端首次安装、健康检查与公开初始凭据登录。
5. 实际 R14 进程持有数据锁时拒绝离线改写。
6. 重置后新账号登录成功、旧账号失败，其他配置保留且不落明文密码。
7. 修改 Web 端口后新监听生效、旧端口释放、账号保留。
8. 新端口已占用时在停止服务之前拒绝操作。
9. 修改配置后注入健康检查失败，恢复原数据并重启原服务。
10. 更新保留账号、Web 端口及主动停止状态。
11. 更新启动失败时恢复旧程序指针与数据。
12. 本地端以普通用户安装运行，服务内存锁定额度正确，控制台链接可取且日志隐藏密钥。
13. 本地端真实 systemd 启动、停止与重启。
14. 两端卸载保留运行数据与备份。

6 项补充场景：公网地址证书经回环连接校验；安全路径与已开启两步验证在真实 R14 中保留；既有单元通过覆盖文件更新而保留原单元和环境；卸载前备份失败恢复运行；接管时保留主动停止状态；接管后的卸载保留原单元和数据。接管测试使用独立服务单元，原启动器路径的 systemd 元数据按 R14 标准部署模拟，不代表所有自定义部署均已验证。

7 项离线回归测试位于 `tests/test_manager.py`，覆盖两步验证及其他配置保留、端口局部修改、不支持的格式和权限、符号链接与硬链接拒绝、原子替换故障、下载重定向限制、日志密钥隐藏。在隔离 Linux 测试环境以 root 运行：

```bash
sudo python3 tests/test_manager.py
```

更新场景使用已验证的同一软件包赋予测试版本标签，验证版本切换、回退和状态保持；没有伪造新产品版本或上传测试包。

## 边界

- 本轮不是所有 Linux 发行版、所有历史部署、实体矿场主机的兼容性认证。
- 软件包 SHA-256 来自官方 HTTPS 发布清单，未提供独立发布者数字签名。
- 自生成证书路径已实际验证；本轮未向公共 CA 申请证书，未验证所有自定义证书组合。
- 本地端凭据重启后须交互解锁。脚本不保存解锁密码、不更改两步验证、不自动放行防火墙。
- 数据和操作备份在卸载后保留；脚本不提供自动彻底清空数据功能。
